# ローマ字問題と誤答学習

ローマ字と文脈から問題を作り、共通コアに一文字ずつ入力します。合成文脈は隔離されたFFIセッションに確定し、その後にローマ字を入力してSpaceで候補生成します。アプリへの文章送信はありません。

確認済みの36題を6分野に分け、毎回各分野4問を輪番で出題します。3回のバッチで36題を一巡し、学習しない固定6題（各分野1問）を別に評価します。教師が作る文脈を追加し続ける方式は停止しました。Qwenにはローマ字・パーサーの読み・文脈と、誤答／確認済み正解の候補を与え、候補の順序を入れ替えて二度判定させます。学習に使わない自由な文章生成は高速化のため実行しません。

誤答を学習する条件は、練習問題であること、現在の練習アプリの回答が正解と異なること、教師が候補の順序を入れ替えた2回の比較で、いずれも確認済みの正解を選ぶことです。主画面には候補比較の判定を表示します。教師の自由変換案は実行記録に残しますが、主画面には表示しません。教師の自由変換が文脈の言い換えになってしまう場合でも、その案自体を正解として学習しません。Qwen自身の誤りは実行記録で確認できます。

採用した誤答と正解でネイティブ候補ランキングモデルを再学習し、同じローマ字・同じ文脈で使う練習用の訂正記憶を更新します。練習アプリでは、同じ入力・文脈でコアの第一候補と記憶にある候補を学習済みの重みで比較して回答します。候補が記憶にない入力には適用しません。モデルとデータのSHA-256、学習の再現性、評価題の混入防止を検証してから訂正記憶を公開します。過去の学習例は最大96件保持し、再学習で維持します。

画面の「学習アプリの回答」はこの訂正記憶も使います。同じ問題での改善は記憶による改善を含みます。未知の文章への汎化能力を証明する値ではなく、稼働中IMEの辞書・モデルにも自動適用しません。

人による回答は不要です。常駐処理はアプリ起動中に、問題生成・検証用コアへの一文字ずつの自動入力・変換・教師比較・誤答学習・評価を繰り返します。画面は回答欄を初期状態で隠し、変換結果・教師の候補判定・正解・学習状況を自動表示します。「自分の回答も比較する」を選んだ場合だけ、任意の回答欄を表示します。「回答して比較」で自分の答えを端末内に保存できます。自分の回答は自動学習の正解として扱わず、外部に送信しません。回答の保存は最大96件です。APIはループバックのみ、Origin・Host・JSON形式・文字数・問題IDを検証します。

実行中の各バッチは `scripts/distill-qwen.py --romaji-practice` を利用します。成果物は `.cache/app-learning/runs/`、画面用結果は `practice-results.json`、練習用訂正は `practice-memory.json`、自分の回答は `practice-answers.json` に保存します。モデルは検証用のままです。

検証: `python scripts/test-romaji-practice.py` と `python scripts/test-learning-dashboard.py`。固定テストのローマ字19例は別に測定し、今回の誤答学習に混ぜません。

最初の候補比較による誤答学習を含む実行では、固定15問の練習アプリ回答は7/15から13/15になり、6件の誤答を採用しました。評価専用3問は学習せず、学習前後とも3/3です。これは同じ入力・文脈の学習結果を含む値で、未知文の改善ではありません。モデルのSHA-256・学習データ・再現性を検証済みです。記録は `benchmarks/results/romaji-practice-first.json`。

画面の学習状態は、今回の誤答学習、過去の学習による訂正、コアが最初から正答、教師判定の不一致・エラーによる保留、評価専用を区別します。既存の採用済み例は毎回の学習データに再利用しており、「今回追加なし」は学習データから除外したという意味ではありません。

高速化: 使われない自由変換の推論を各問題で行う処理を削除しました。教師への候補判定は未訂正の誤答だけ二度行い、既存の正答は再確認不要です。正答もコアで一文字ずつ変換し、学習・SHA-256・再現性検証は維持します。常駐教師はCPU4スレッド、バッチ間の休憩は10秒です。教師モデルの重み自体は更新しません。

偏りを抑える仕組み: 同音異義語、技術用語、天気・自然・食べ物、気持ち・交流、日常文、記号・外国語を均等に出題します。訂正記憶は分野ごと最大16件、同じ読みは文脈を変えても最大2件です。学習データは存在する各分野の重み合計を1に揃え、採用件数の多い分野が学習を独占しないようにします。検証・評価データの重みは変更しません。分野名と配分は画面と実行記録に表示します。候補の順序を二度替える教師判定も維持します。

36題は限定された合成例です。実際の全言語・全分野の分布を代表せず、評価専用6題も網羅的な精度評価ではありません。データ量を均等にしても完全な無偏りは保証できません。確認済みの問題集と独立した評価セットを引き続き拡充する必要があります。

新規生成モード: 固定問題とは別にQwenへローマ字・ひらがな読み・表記・短い背景の新しい組を要求します。各分野最大1問、1バッチ最大6問。既出ローマ字は`generated-inputs.json`で除外し、最大96件の訂正記憶とは分離します。読み一致とコア候補内の表記を条件に、二度の教師判定で確認できた誤答だけ検証用モデルへ採用します。画面では「Qwen新規生成・暫定正解」と表示します。生成失敗・重複で0問の場合もあります。教師は自身の誤りを見逃す可能性があり、この自己判定による採用は独立した正解確認ではありません。固定評価例への混入を防ぎ、稼働中IMEへ自動反映しません。

生成問題の事前除外: ローマ字と生成読みの不一致、提案表記がネイティブ候補に存在しない例は、問題一覧の公開前に除外します。「supper→夕食」など翻訳の問題はローマ字変換問題として掲載しません。除外件数と理由を監査記録に保存し、画面では除外件数を表示します。以前の結果についても不正な生成例を主問題一覧から除外して表示します。モデルで候補を生成できない正しい例も保守的に除外され得るため、除外を意味の誤りと断定しません。
