# 訓練データだけによるスコア尺度の診断

2026-10-13。候補ペアでの正解数に比べて、実辞書の順位付けに新しいモデルが十分影響しない可能性を調べました。小さなモデルスコアと辞書スコアの単位が異なるためです。

Rustのpair-auditに訓練ペアの絶対スコア差の中央値を追加しました。偶数件は中央二件の平均を使います。validation/testはこの値の算出に使わず、評価用の候補を変更しても補正値が変わらないことをテストしています。値は確率・信頼度ではありません。

研究用のNeuralRanker::from_bytes_with_temperatureは、既存候補のモデルスコアから候補間の平均を引き、明示的に渡した尺度で割ります。辞書へ加える影響は引き続き±2048です。未知の候補を生成せず、同点処理・元読みを保持します。有限の0.0001～100の値だけを受け付け、既定のfrom_bytesは従来の計算を維持します。単独候補や共通スコアのずれ、影響の上限をテストしました。

既存の研究モデルと訓練86例から得た尺度は0.013075330294668674です。モデル・教材のSHA-256を含むscale-audit-v2.jsonに記録しました。補正値を評価結果に合わせて探索していません。

同じ実辞書と固定validation12文では、新Rust経路の第一候補が4/12から2/12へ退行しました。二例が正答から誤答になり、新しく正答になった例はありません。正解候補は6/12で変わりません。弱い学習結果の影響を強めるだけでは改善しないという診断です。補正は不採用にし、既定のモデル・稼働IMEは変更しません。

Windowsでの今回のウォームキャッシュp95は35.69ms。別プロセスの負荷を含み、速度改善とは報告しません。通常変換90%・5ms・誤字80%は未達です。候補ペアと変換全体の精度を分け、訓練の意味・誤候補の質と未知文への汎化をさらに改善する必要があります。

```powershell
cargo run --release -p luqnexa-ml --features trainer --bin pair-audit -- MODEL.lqml TRAINING.jsonl
cargo run --release -p nextime-core --features mobile-neural --example evaluate_neural -- MODEL.lqml DATA.jsonl validation BASE.nud OVERLAY.nxl --temperature TRAINING_DERIVED_VALUE
```

補正値はモデル・教材のハッシュと対応を確認してから明示的に使います。自動ロード・外部送信・予定学習は行いません。
