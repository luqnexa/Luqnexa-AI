# アプリ起動中の問題作成・学習ループ

2026-10-12に、毎時の学習からローカル常駐処理へ変更した。ここでいうアプリはこのチャットのCodexデスクトップアプリ。現在のユーザーの `%LOCALAPPDATA%/OpenAI/Codex/` 配下にあるCodexプロセスを確認して学習する。アプリを閉じたときは、進行中の教師リクエストの完了後に停止し、再起動を待つ。停止は瞬時ではなく、教師リクエストには最大120秒のタイムアウトがある。実アプリを閉じての確認は行っていない。閉じているときに学習を起動しないことと停止信号は単体テストで確認した。

常駐スクリプトは `scripts/learn-while-app.py`。1回に最大4組を作成し、Qwenの候補判定、独自ランキングモデルの学習、固定テストの評価、重みの再現性とSHA-256の検証を行い、60秒休んで繰り返す。Qwenは2スレッドと通常より低い優先度で起動する。入力への影響を完全に防ぐ保証や、実機での消費電力評価はない。

試運転では自由に候補を生成させると同じ文字列を正誤両方に出した。そのため、確認済みの12種類の表記ペアを問題の材料に固定し、Qwenには直前の文脈を作らせる方式へ変更した。これは無制限の語彙や分野を自動獲得する方式ではない。同じ問題は除外し、順番を入れ替えても教師が参照表記を選ぶ例だけ採用する。生成した文脈は暫定であり、Qwenの自己判定は独立した正解確認ではない。

最初に固定した学習例とテストは維持し、新しく生成した学習例は直近96組まで使用する。過去の成果物はrunごとに保存するが、古い追加例を重みへ永久に蓄積する方式ではない。同じ例の判定は、文脈・候補・教師モデル・プロンプトが一致する場合にキャッシュから再利用する。

最初の成功した試運転は97.22秒、新規3組が採用された。固定の未学習8組の重みだけの比較は7/8を維持した。適用範囲を含む評価では8組とも同点であり、実際のIMEの未知文で精度向上を達成したとは扱わない。[実測記録](../benchmarks/results/app-learning-first.json)を参照。単体テスト13件が成功した。

個人の入力内容や他アプリの会話は取得しない。モデルは `.cache/app-learning/runs/`、最新結果は `.cache/app-learning/latest.json`、状態は `.cache/app-learning/status.json` に保存する。稼働中IMEのモデルを置き換えない。

## 起動・停止

```powershell
# 起動し、ユーザーのWindowsログイン後にも監視を起動する
pwsh -NoProfile -File scripts/start-app-learning.ps1 -RegisterStartup

# 学習を無効にし、ログイン時の起動登録を解除する
pwsh -NoProfile -File scripts/stop-app-learning.ps1

# 再開する
pwsh -NoProfile -File scripts/start-app-learning.ps1 -RegisterStartup
```

HKCUのRun項目 `LuqnexaAppLearning` を使用する。管理者権限は不要。アプリが閉じている間は15秒間隔の起動確認のみを行い、Qwenで学習しない。停止設定は `.cache/app-learning/disabled`。二重起動はOSのファイルロックで防ぐ。

以前の毎時自動化 `luqnexa-qwen` は「Luqnexa常駐学習の監視」へ変更した。毎時の監視は別の学習を起動せず、正常処理・待機・休憩では通知しない。停止や失敗、検証済みの意味ある改善を通知する。

## 学習状況アプリ

デスクトップの「Luqnexa 学習状況」から開ける。Edgeがある場合は独立したアプリ風ウィンドウ、なければ既定ブラウザーで表示する。以下のコマンドでも開ける。

```powershell
pwsh -NoProfile -File scripts/open-learning-dashboard.ps1
```

画面は4秒ごとに更新し、問題の文脈生成・候補判定・モデルの検証・休憩・停止を表示する。前回の生成数、採用・除外件数、所要時間、候補比較評価、適用範囲を含む評価、SHA-256照合、IMEへの反映状況、最近10回の履歴、今回の問題案が見える。生成段階には実測の件数進捗がないため、推測のパーセントは表示しない。履歴の採用数は既存例を含む各回の件数であり、累積の新規学習件数ではない。

上部の「いま判定している文章」に、進行中の一組の文脈・参照候補・比較候補と通常順／入替順の処理段階を表示する。教師処理が `current-question.json` に実際の対象を記録する。「今回の問題一覧」では学習候補全文とQwenの通常順／入替順の選択、採用・除外・未判定・エラー、過去の判定の再利用を確認できる。文脈生成中は判定対象を推測せず、その旨を表示する。ローマ字入力からIME全体を測る方式ではなく、候補文章の比較を可視化した画面である。

Python標準ライブラリだけで動作し、サーバーは127.0.0.1のみで待ち受ける。外部のフォントやスクリプトは使わない。表示は読み取り専用で、入力・学習設定・モデルを変更しない。別プロセスのため、画面を閉じても学習は継続する。状態ファイルのPIDだけで判断せず、監視プロセスの実行ファイルとスクリプトを確認する。確認結果は10秒間キャッシュする。

ダッシュボードのテスト4件が成功した。実際の画面で状態、件数、評価、整合性、履歴の表示を確認した。モバイル実機・各種ブラウザーの動作は未検証。


### ローマ字入力・絵文字の変換評価

画面上部の「ローマ字入力からの変換テスト」に、固定19例の入力、期待する表記、実際の第一候補、一致・不一致を表示します。`tests/romaji-symbols.tsv` を一文字ずつFFIに入力し、Spaceで候補を生成します。`まるいち → ①`、矢印、星、ハート、絵文字6種、`あにゅはせよ / あんにょんはせよ → 안녕하세요`を含みます。韓国語全体の翻訳・入力への対応ではありません。

`.cache/app-learning/romaji-config.json` に指定したビルド済みDLLと辞書を、各学習バッチの開始時に再測定します。結果は原子的に `romaji-results.json` に保存します。固定評価例は教師・生徒の学習データに混ぜません。Qwenで学習した未適用モデルの評価ではなく、設定されたネイティブコアの評価です。同じビルドを繰り返してもその変換能力は変わりません。稼働中IMEへの反映状況とも別です。

専用の読み（例 `えがおえもじ`）から絵文字を選び、Enterで確定します。一般的な語を勝手に絵文字に置き換えません。絵文字の見た目は利用先のフォントに依存します。

2026-10-12 の固定19例測定は19/19一致、開発PCでp95 0.364 ms（100回、20回のウォームアップ）。iPhone SE・1億エントリ・UI描画を含む測定ではありません。対象DLL SHA-256: `499a6a29806984401790efe1115a8a2ba38f06f3b0bb1bc1250b9d5debc11d37`。


## 現在の学習方式

ローマ字からの実変換・教師回答・誤答学習・自分の回答の比較を追加しました。常駐処理は `--romaji-practice` モードを使います。従来の完成文章の二択だけを繰り返す方式から切り替えています。詳細は [ローマ字問題と誤答学習](romaji-practice.md) を参照してください。

現在の高速モードはCPU4スレッド・バッチ間休憩10秒です。学習に使わない自由変換の推論を省き、未訂正の誤答だけを候補順序を替えて二度確認します。各バッチのコア変換、再学習、ハッシュ・再現性確認は維持します。実行記録の処理時間は高速化前231.59秒（19問）、変更後52.70秒（19問）。生成文脈と誤答件数が異なる連続バッチの比較で、教師起動と外側の再検証は計測外です。固定条件の速度倍率を示すものではありません。記録: `benchmarks/results/app-learning-speed.json`。

偏りの抑制: 現在は確認済み36題を6分野から各4問ずつ輪番で出題し、各分野1問の評価専用データは学習から隔離します。Qwenの文脈追加は停止し、同じ読みの大量追加を防ぎます。採用済みの記憶は読みごと最大2件・分野ごと最大16件。学習データは存在する各分野の重み合計を均等にします。有限の合成問題による対策であり、完全な無偏りや未知文の改善を保証しません。

現在はQwenによる新規問題生成を再開しました。各分野最大1問を追加し、固定24問＋評価6問と一緒に処理します。既出ローマ字を保存して重複を除外します。生成された正解は暫定で、独立した確認済み正解と分けて表示します。生成問題の学習は、ローマ字からの読みが一致し、提案正解がコアの候補に存在し、二度の候補判定が一致した誤答に限定します。教師の自己判定は独立した精度検証ではありません。未採用問題も監査記録に残します。生成処理で所要時間は増加し、常に6問を採用できる保証はありません。

表示は「いま実行中」「今回の結果」「過去の履歴・評価」の3画面に分離しました。初期画面は現在処理する1問のみ。問題生成中・検証中・休憩中は前の問題を表示しません。比較の基準とコア／学習アプリ／教師の役割は画面の「見方・各欄の意味」で確認できます。結果画面では次の問題生成中に直近の完了結果である旨を明記します。

大文字小文字の教師判定: Python、Rust、GitHub、Windows、Linux、TypeScript、JavaScript、VSCode、AI、CPU、GPU、API、JSON、SSHは候補中の正式表記を完全一致で検査します。教師が誤ったケースを選んだ場合はCasingErrorとして採用を保留します。文脈で変数名・識別子・関数名を引用指定した場合はそのケースを保持します。これは検証用の教師判定の改善で、稼働中IMEの修正ではありません。

固定問題は復習・評価として扱い、結果画面では初期状態で新規生成のみ表示します。新規0問の場合はその旨を明示します。候補・読み・文脈・教師コード・教師モデルSHA-256が同じ候補判定は再利用し、判定不一致でも同じ条件で繰り返し問い合わせません。教師処理エラーはキャッシュしません。生成した答えがひらがなの読みのコピーだけの場合は学習から除外し、既存の該当生成記憶も次回の再構築で採用を取り消します。過去のrun成果物・prior-memory.jsonは監査用に保持します。固定問題の復習とモデルの再検証自体は続きます。
